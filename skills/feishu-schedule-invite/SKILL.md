# 飞书智能日程邀约

## ⚠️ 前置条件：权限授权

**使用此 skill 前，必须确保已开通以下飞书权限：**

### 必需权限列表

| 权限 | 说明 | 用途 |
|------|------|------|
| `contact:user.base:readonly` | 获取用户基本信息 | 搜索参与人 |
| `calendar:calendar` | 日历读写 | 查询忙闲、创建日程 |
| `calendar:calendar_event` | 日程管理 | 创建、修改日程 |
| `calendar:room:readonly` | 会议室忙闲查询 | 查询会议室可用性 |
| `im:chat.members:read` | 获取群成员列表 | 从群聊邀约成员 |

### 权限授权方式

**一次性批量授权**：
```
使用 feishu_oauth_batch_auth 工具一次性授权所有权限
```

> ⚠️ 如果权限不足，操作过程中会提示授权。建议首次使用时一次性完成所有授权。

## 核心原则

### 1. 不确定就问
- 参与人不确定？→ 问
- 时间不确定？→ 问
- 地点/会议室不确定？→ 问

### 2. 会议时间段限制
**只在以下时间段安排会议（避开吃饭时间）：**
- ✅ **上午**: 10:00-12:00
- ✅ **下午**: 14:00-18:00
- ✅ **晚上**: 19:00-21:00

**避开的时间段：**
- ❌ 12:00-14:00（午休）
- ❌ 18:00-19:00（晚餐）
- ❌ 09:00-10:00（早会/晨会时间，非必要不安排）
- ❌ 21:00 以后（非工作时间）

### 3. 简化确认流程
- ✅ **一次性推荐**：时间 + 会议室一起推荐
- ✅ **提供备选**：列出其他可选方案
- ✅ **减少交互**：用户只需确认一次即可

## 核心流程

```
用户请求 → 提取信息 → 确认信息 → 查询忙闲+会议室 → 推荐方案 → 用户确认 → 创建日程 → 完成
```

### Step 1: 信息提取与确认

从用户消息中提取以下信息，**任何不确定的信息都要向用户确认**：

| 信息项 | 提取方式 | 默认值 | 必须确认 |
|--------|---------|--------|----------|
| 日程主题 | 直接提取或推断 | "会议" | ❓ 不确定时确认 |
| 参与人 | 姓名/部门/群名 | - | ✅ **必须确认** |
| 时长 | 数字+单位 | 1小时 | ❓ 不确定时确认 |
| 时间范围 | 时间表达 | 下一个工作日 | ✅ **必须确认** |
| 是否需要会议室 | 关键词"线上会议"表示不需要 | ✅ **默认需要** | ❓ 仅用户说"线上会议"时才不需要 |

**示例对话**：

```
用户: 帮我约明天下午和影子、卓洛开个会

助手: 好的，我理解您的需求：
📅 主题：会议（请确认）
👥 参与人：影子、卓洛、你
⏰ 时间：明天下午
📍 时长：1小时
🏢 会议室：需要（默认）

请确认以上信息是否正确？
```

> 💡 **默认需要会议室**：除非用户明确说"线上会议"，否则默认需要预订会议室。

---

### Step 2: 查询流程（串行）

> ⚠️ **重要**：必须先查忙闲，确定共同空闲时间后，再查询该时间段可用的会议室

#### 2.1 查询参与人忙闲（第一步）

**工具**: `feishu_calendar_freebusy`

**流程**:
1. 解析参与人姓名为 open_id
2. 确定查询时间范围（根据用户需求）
3. 调用 `feishu_calendar_freebusy` 查询忙闲
4. **只筛选符合会议时间段的时间段**（10-12、14-18、19-21）
5. 得出共同空闲时段列表

**输出示例**:
```
下周一（4月7日）共同空闲时段：
✅ 10:00-12:00（符合会议时间）
✅ 14:00-15:00（符合会议时间）
✅ 15:00-16:00（符合会议时间）
✅ 17:00-18:00（符合会议时间）
```

#### 2.2 查询会议室（第二步，依赖忙闲结果）

> **关键**：必须根据共同空闲时间去查询会议室可用性

**从记忆获取职场信息**：
- 查看 MEMORY.md 中用户的职场位置
- 如果没有，询问用户职场位置并记录

**查询会议室可用性**：

使用 `feishu-room-search` skill 中的 **查询会议室忙闲状态** 接口：

```bash
GET https://open.feishu.cn/open-apis/meeting_room/freebusy/batch_get
```

**参数**:
- `room_ids`: 会议室ID数组（最多20个）
- `time_min`: 查询起始时间（RFC3339格式，需URL编码）
- `time_max`: 查询结束时间（RFC3339格式，需URL编码）

**判断逻辑**:
- `free_busy[room_id]` 为空数组 → 会议室该时段空闲 ✅
- `free_busy[room_id]` 有数据 → 会议室该时段已被占用 ❌

**查询流程**:
1. 从 MEMORY.md 获取职场会议室列表
2. 针对每个共同空闲时段，调用忙闲接口
3. 筛选出空闲的会议室
4. 返回：时间段 → 可用会议室列表

**示例结果**：
```
共同空闲时段 → 可用会议室：
- 16:00-17:00 → 星火燎原(14人)、效率(9人)、稳定(9人) ✅
- 19:00-20:00 → 所有会议室可用 ✅
```

> 📖 详细接口说明见 `feishu-room-search` skill

**注意**：如果会议室不可在线预订，需要提示用户

### Step 3: 一次性推荐方案

> **重要**：推荐时必须同时展示时间和对应的可用会议室，不能显示"待定"

**推荐格式**：

```
根据参与人忙闲情况和会议室可用性，我为您推荐以下方案：

## 💡 推荐方案

**📅 时间**: 下周一（4月7日）14:00-15:00
**🏢 会议室**: 星火燎原(视频会议) - 14人
**📍 地点**: 长沙研发中心 42F

---

## 🔄 其他可选方案

**上午时段**：
- 10:00-11:00 → 星火燎原(14人) / 培训室4201(21人)

**下午时段**：
- 14:00-15:00 → 星火燎原(14人) / 培训室4201(21人) ⭐推荐
- 15:00-16:00 → Pioneer(10人) / 效率(9人)
- 17:00-18:00 → Pioneer(10人) / 效率(9人)

---

请确认是否使用推荐方案？
- 回复"确认"或"✅"使用推荐方案
- 回复"方案X"选择其他方案（如"方案2"）
- 回复"修改"调整需求
```

> ⚠️ **禁止**：推荐时会议室显示"待定"或空白

---

### Step 4: 最终确认（创建前）

> **重要：创建日程前必须确认！**

**确认内容**：

```
请确认日程信息：

📅 主题：2026Q2目标对齐
⏰ 时间：2026-04-07 14:00-15:00
👥 参与人（10人）：阿振、小平、居右、洋洋、孤城、川禾、山筑、玛卡、魏命名、弗罗格
🏢 会议室：星火燎原(视频会议)
📹 视频会议：自动生成

确认创建？
- 回复"确认"创建日程
- 回复"修改"调整信息
```

**必须确认的场景**：
- ✅ 每次创建日程前都要确认
- ✅ 预定会议室前必须确认
- ✅ 如果用户说"修改"，询问需要修改的内容

### Step 5: 创建日程

**工具**: 
- `feishu_calendar_event` (创建日程)
- `feishu_calendar_event_attendee` (添加参会人)

**流程**:
1. 使用确认后的信息创建日程
2. 添加所有参与人为参会人
3. 添加会议室为资源参会人（如需要）
4. 设置提醒（默认提前15分钟）

**参数示例**:
```json
{
  "action": "create",
  "summary": "2026Q2目标对齐",
  "start_time": "2026-04-07T14:00:00+08:00",
  "end_time": "2026-04-07T15:00:00+08:00",
  "attendees": [
    {"type": "user", "id": "ou_xxx"},
    {"type": "resource", "id": "omm_xxx"}
  ],
  "user_open_id": "ou_aa94092a6fd14dd0672a7f327a00fd61"
}
```

## 边界情况处理

### 1. 无法识别参与人

```
助手: 我找到了多个名为"影子"的用户：
1. 影子(Phantom) - 技术平台
2. 影子(Shadow) - 国际技术

请问您指的是哪一位？
```

### 2. 没有共同空闲时间

```
助手: 抱歉，下周一所有参与人没有共同的空闲时段。

忙碌情况：
- 小平：10:30-12:00 有会议
- 阿振：15:30-17:00 有会议

建议：
1. 调整到其他时间（如周二、周三）
2. 改为部分参与人参会
3. 调整会议时长

您希望如何处理？
```

### 3. 会议室不可用

```
助手: ⚠️ 提示：长沙42F会议室暂不可在线预订

可选方案：
1. 改为线上会议（使用飞书视频会议）
2. 您联系会议室管理员预订后，我再创建日程
3. 查询其他地点的会议室

您希望如何处理？
```

### 4. 用户记忆中没有职场信息

```
助手: 我还没有记录过您的职场信息。
请问您在哪个地点办公？
- 长沙研发中心（长研）
- 上海办公室
- 其他地点

（我会记录下来，下次就不用再问了）
```

**记录到 MEMORY.md**：
```markdown
## 用户偏好

- 🏢 职场: 长沙研发中心（长研）
- 📍 楼层: 42F
- ⏰ 偏好会议时间: 10-12点、14-18点、19-21点
- 📅 默认会议时长: 1小时
```

### 5. 用户中途修改需求

```
用户: 把时间改成周二吧

助手: 好的，我重新查询周二的可用方案...

周二（4月8日）推荐方案：
📅 时间: 14:00-15:00
🏢 会议室: 星火燎原(视频会议) - 14人

其他可选时段：10:00-11:00、15:00-16:00、17:00-18:00

请确认？
```

## 关键提醒

✅ **必须做的**：
1. 首次使用时提示用户授权所有权限
2. 参与人列表必须确认
3. 会议时间必须符合 10-12、14-18、19-21 时间段
4. 一次性推荐时间+会议室，减少确认次数
5. 创建前必须展示完整信息并确认

❌ **不要做的**：
1. 不要在非会议时间段安排会议（避开吃饭时间）
2. 不要猜测用户的意图
3. 不要在用户未确认时就创建日程
4. 不要假设用户的职场位置

## 性能优化

- ✅ 并行查询忙闲和会议室
- ✅ 缓存用户职场信息到 MEMORY.md
- ✅ 缓存会议室列表，避免重复查询
- ✅ 优先使用记忆中的偏好信息
