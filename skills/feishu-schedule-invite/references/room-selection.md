# 会议室选择策略

## 核心原则

> ⚠️ **不要假设，从记忆中获取用户偏好，不知道就问**

---

## 会议时间段限制

**只在以下时间段安排会议：**
- ✅ **上午**: 10:00-12:00
- ✅ **下午**: 14:00-18:00
- ✅ **晚上**: 19:00-21:00

**必须避开的时间段：**
- ❌ 12:00-14:00（午休）
- ❌ 18:00-19:00（晚餐）
- ❌ 09:00-10:00（早会/晨会时间）
- ❌ 21:00 以后

---

## Step 1: 获取用户职场信息

### 1.1 从记忆中获取

**优先查看 MEMORY.md**：
```markdown
## 用户偏好

- 🏢 职场: 长沙研发中心（长研）
- 📍 楼层: 42F
```

### 1.2 如果记忆中没有

**直接询问用户**：

```
助手: 我还没有记录过您的职场信息。
请问您在哪个地点办公？
- 长沙研发中心（长研）
- 上海办公室
- 其他地点

（我会记录下来，下次就不用再问了）
```

**记录到 MEMORY.md**：
```markdown
## 用户偏好

- 🏢 职场: 长沙研发中心（长研）
- 📍 楼层: 42F
- ⏰ 偏好会议时间: 10-12点、14-18点、19-21点
- 📅 默认会议时长: 1小时
```

---

## Step 2: 筛选合适时间段

### 2.1 根据忙闲筛选

从参与人忙闲情况中，**只保留符合会议时间段的空闲时段**：

```
原始空闲时段：
- 09:00-10:00 ❌ 不符合（早会时间）
- 10:00-12:00 ✅ 符合
- 12:00-14:00 ❌ 不符合（午休）
- 14:00-15:00 ✅ 符合
- 15:00-16:00 ✅ 符合
- 17:00-18:00 ✅ 符合
- 18:00-19:00 ❌ 不符合（晚餐）
- 19:00-21:00 ✅ 符合

筛选后的可用时段：
✅ 10:00-12:00
✅ 14:00-15:00
✅ 15:00-16:00
✅ 17:00-18:00
✅ 19:00-21:00
```

### 2.2 推荐优先级

**优先推荐**：
1. 下午时段（14:00-18:00）- 最常见的会议时间
2. 上午时段（10:00-12:00）- 适合快速对齐
3. 晚上时段（19:00-21:00）- 非必要不推荐

---

## Step 3: 查询会议室

### 3.1 确定会议室需求

- **容量**: 根据参与人数确定（至少容纳所有人）
- **地点**: 根据用户职场确定
- **设备**: 默认需要视频会议设备
- **时间**: 已筛选的可用时段

### 3.2 调用 feishu-room-search skill

**直接调用 skill 获取可用会议室**：

```javascript
const rooms = await feishu-room-search({
    location: '长沙研发中心',
    capacity: 10,
    timeRange: {
        start: '2026-04-07T14:00:00+08:00',
        end: '2026-04-07T15:00:00+08:00'
    }
});
```

**返回格式**（由 feishu-room-search 处理所有判断逻辑）：
```javascript
[
    {
        name: 'Pioneer(视频会议)',
        capacity: 10,
        roomId: 'omm_xxx',
        location: '长沙研发中心 42F',
        isAvailable: true,
        status: 'enabled'
    }
]
```

**重要**：
- ✅ feishu-room-search 会判断会议室可用性
- ✅ 只返回可用的会议室
- ✅ 如果会议室不可用，不会在列表中

### 3.3 处理查询结果

**如果返回空列表**：
```
助手: 抱歉，该时段没有可用的会议室。

可选方案：
1. 调整时间：15:00-16:00 有会议室可用
2. 改为线上会议

您希望如何处理？
```

**如果有可用会议室**：
```
找到以下可用的会议室：

🏢 Pioneer(视频会议) - 10人
   📍 长沙研发中心 42F

🏢 星火燎原(视频会议) - 14人
   📍 长沙研发中心 42F
```

---

## Step 4: 一次性推荐时间 + 会议室

> **重要：将时间和会议室一起推荐，减少确认次数**

### 4.1 推荐格式

```
根据参与人忙闲情况，我为您推荐以下方案：

## 💡 推荐方案

**📅 时间**: 下周一（4月7日）14:00-15:00
**🏢 会议室**: 星火燎原(视频会议) - 14人
**📍 地点**: 长沙研发中心 42F

---

## 🔄 其他可选方案

**上午时段**：
- 10:00-11:00 - 星火燎原(14人) / 培训室4201(21人)

**下午时段**：
- 14:00-15:00 - 星火燎原(14人) ⭐推荐
- 15:00-16:00 - Pioneer(10人) / 效率(9人)
- 17:00-18:00 - Pioneer(10人) / 效率(9人)

**晚上时段**：
- 19:00-20:00 - Pioneer(10人)

---

请确认是否使用推荐方案？
```

### 4.2 推荐原则

**时间推荐**：
- 优先推荐下午时段（14:00-18:00）
- 次优先推荐上午时段（10:00-12:00）
- 尽量避免晚上时段

**会议室推荐**：
- 容量合适（参与人数 ≤ 容量 ≤ 参与人数 × 1.5）
- 有视频会议设备
- 同楼层优先
- 最近使用过的优先

---

## Step 5: 最终确认

> **重要：创建日程前必须确认！**

```
请确认日程信息：

📅 主题：2026Q2目标对齐
⏰ 时间：2026-04-07 14:00-15:00
👥 参与人（10人）：阿振、小平、居右等
🏢 会议室：星火燎原(视频会议)
📹 视频会议：自动生成

确认创建？
```

## 特殊情况处理

### 1. 用户没有提供会议室需求

```
助手: 请问是否需要预定会议室？
- 需要（线下会议）
- 不需要（线上会议）
```

### 2. 会议室预订失败

**如果添加会议室时失败**：

```
助手: ⚠️ 会议室预订失败：[错误原因]

可选方案：
1. 选择其他会议室
2. 调整会议时间
3. 改为线上会议

您希望如何处理？
```

### 3. 所有会议室都已占用

```
助手: 抱歉，该时段所有会议室都已占用。

可选方案：
1. 调整时间：15:00-16:00 有会议室可用
2. 改为线上会议

您希望如何处理？
```

### 4. 用户职场信息需要更新

```
用户: 我在上海，不在长沙

助手: 好的，我会更新您的职场信息。

请问上海办公室的具体位置是？
（我会记录到记忆中）
```

## 性能优化

- ✅ 从 MEMORY.md 获取用户偏好，避免重复询问
- ✅ 缓存会议室列表，减少查询次数
- ✅ 并行查询忙闲和会议室
- ✅ 一次性推荐时间+会议室，减少交互次数

---

## 职责边界

**feishu-schedule-invite 负责什么**：
- ✅ 日程邀约流程编排
- ✅ 时间段筛选（避开吃饭时间）
- ✅ 推荐方案生成
- ✅ 用户交互和确认
- ✅ 创建日程

**feishu-room-search 负责什么**：
- ✅ 查询会议室列表
- ✅ 判断会议室可用性
- ✅ 返回可用会议室
- ✅ 处理会议室状态判断的技术细节

**清晰的边界**：
- feishu-schedule-invite 不关心会议室状态如何判断
- feishu-room-search 封装所有会议室相关的技术细节
